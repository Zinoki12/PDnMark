# Проблема и цель
Для начала стоит разобраться с предметной областью, объектом и предметом.

Предметной областью выступает разметка банковского хранилища персональных данных. 

Объектом выступает постоянно пополняющиеся банковско хранилище данных

Ну и предмет - разметка постоянно пополняющегося банковского хранилища

## Процесс
Опишем сам процесс, заинтересованное лицо, которое мы опишем далее, отсылает данные в банковское хранилище, но в этих данных есть возможные пдн, соотвественно эти данные надо разметить. Итого получается схема:

```text
Заинтересованное лицо -> разметка человеком -> банковское хранилище
```
                            

## Недостатки
Опишем недостатки данной схемы.

#### 1. Скорость
Данные могут быть очень большого размера, от нескольких мегабайт вплоть до терабайт. Количество обрабатываемых строк могут переваливать за несколько тысяч. Человек, в свою очередь, медленно обрабатывает информацию, что может привести к длительным застоям

#### 2. Точность и полнота
Человек из-за невнимательности и усталости может или пропускать целые строки, потенциально хранящие пдн, или просто упустить ячейку с пдн

## Цель
Исходя из вышесказанного, можно вынести вывод: человек не подходит для роли разметчика пдн в банковских хранидищах. Следовательно нам нужен некоторый программный аппарат, который будет удовлетворять особым требованиям. В свою очередь аппарату нужен инструмент, с помощью которого он будет способен совершать разметку, а для инструмента нужна математическая база - математический аппарат.

Итого получается примерная схема:
```text
Заинтересованное лицо -> инструментарий -> банковское хранилище
        реализация    ↑        ↓       ↓требования
                    программный аппарат
        реализация    ↑        ↓       ↓требования
                        мат аппарат
```
Каждый из этапов предоставляет требования и определенную реализацию. Также требования могут называться ограничениями

## Заинтересованные стороны
Поговорим о том, кому это нужно. С перва-наперва это высший руководительный персонал и отдел юристов. Утечка пдн влечет ответственность по 152-фз РФ. Это дополнительные расходы, а также дополнительная большая работа для юристов
Во вторых - отдел кибербеза. Их заинтересованность заключается в том, что другим отделам должны приходить данные с засекреченным пдн, так как отсутсвие данной ... открывает возможность для слива данных
В третьих - аналитики, ввиду их работы - им требуется чистые данные без всякого шума. Данный программный аппарат как раз будет отсеивать пдн, ненужные для аналитики
