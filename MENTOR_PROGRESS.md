# Менторинг: Go для диплома (классификация ПДн)

## Тема диплома
Сервис автоматической категоризации ПДн/не-ПДн в больших разнородных хранилищах данных, с доступом на базе ролевой модели. Выбрана 2026-08-04 как самая развивающая из трёх вариантов (Go backend + проектирование хранилищ через Data Vault 2.0), в противовес более простым темам (платформа брокерских отчётов, сервис "Карма").

## Формат работы
Ментор даёт теорию, примеры и мини-проекты — **не готовый код**. Студент решает сам, ментор ревьюит как код-ревьюер: что сломается в проде и почему.

## Учебный план (6 этапов)
1. **Горутины, каналы, worker pool** — в процессе
2. `context`: таймауты, отмена, graceful shutdown
3. Go + PostgreSQL: `pgx`, потоковое чтение, `EXPLAIN`, `pg_stats`, `TABLESAMPLE`
4. Интерфейсы и структура проекта (подменяемые источники данных)
5. Каскад классификации: метаданные → статистика планировщика → сэмпл → полный скан; словари, контрольные суммы, метрики precision/recall
6. Data Vault 2.0: хабы/линки/сателлиты, хеш-ключи, псевдонимизация

## Стартовый уровень (замер на 2026-08-04)
По коду в `backend-bridge` и `food-bot`: уверенно — структуры, слайсы, мапы, замыкания (включая замыкания над замыканиями), `http.HandlerFunc`-фабрики, error wrapping через `%w`, table-driven тесты с `t.Run`.

Пробел был конкретно в трёх вещах: `go func` (запуск горутины), `defer`, `sync.WaitGroup` — не в базовом синтаксисе функций вообще (было недопонимание в первом сообщении, поправили).

Известный сломанный тест: `food-bot/education/task24_test.go` (реализация ушла с `strings.Contains` на `HasSuffix`, тест/комментарий остались от старой версии). **Студент решил не чинить — не поднимать эту тему повторно.**

## Журнал прогресса

### 2026-08-04 — Этап 1, старт
Три изолированных упражнения на новые примитивы (`/Users/kirill/diplom/ex.go`):

- **Упр. 1** (`go func` без `WaitGroup`, 5 горутин в цикле): студент сам обнаружил гонку `main` vs горутины — в трёх запусках 3/0/0 напечатанных строк вместо ожидаемых 5. Верно понял суть (гонка), формулировку уточнили: гонка не горутин друг с другом, а `main` против **всех** горутин разом — когда `main` завершается, процесс убивает все недоработавшие горутины без предупреждения.
- **Упр. 2** (тот же код + `WaitGroup`): решил правильно с первого раза. Проверено 5 запусками подряд — стабильно 5 строк.
- **Упр. 3** (порядок нескольких `defer`): предсказал верно (`A C E D B`) до запуска.

Следующий шаг: мини-проект «сканер-лайт» — пул воркеров с фиксированным N (не горутина на задачу), 50 симулированных таблиц, `-race` чисто, тесты на реальное ограничение параллелизма и на отсутствие потерь результатов.

## Заметки по стилю обучения
- Объяснять с нуля именно то, чего не хватает конкретно — не переобъяснять то, что студент уже знает.
- Перед комбинированным мини-проектом — изолированные крошечные упражнения на каждый новый примитив по отдельности.
- Можно ссылаться на «The Go Programming Language» (Donovan & Kernighan) по разделам (defer — §5.8, goroutines — §8.1, sync — гл. 9), без дословных цитат — своими словами + указание, где смотреть в книге.
- Готовый код студенту не даётся никогда, только скелеты формы и разбор.
